# 🛍️ Анализ ассортимента интернет-магазина (ABC/XYZ-анализ)

## 📌 Описание проекта

Провести комплексный анализ ассортимента британского интернет-магазина подарков и товаров для дома на основе транзакционных данных за 14 месяцев. Цель оценить структуру ассортимента, выделить группы SKU по экономической значимости (ABC) и вариативности спроса (XYZ), провести динамический ABC-анализ для отслеживания миграции товаров между категориями, проанализировать сезонность и возвраты, а также сформировать обоснованный список кандидатов на сокращение с оценкой потенциального эффекта.

**Ключевые элементы:**
- **Очистка и предобработка данных:** удаление дубликатов, отмен, служебных операций и аномальных значений, нормализация `StockCode`.
- **ABC-анализ:** классификация товаров по их вкладу в выручку (A - 80%, B - 15%, C - 5%).
- **Динамический ABC-анализ:** отслеживание миграции SKU между категориями по кварталам для выявления «восходящих» (C → A/B) и «падающих» (A/B → C) звёзд.
- **XYZ-анализ:** классификация товаров по коэффициенту вариации спроса (X - стабильный, Y - умеренный, Z - нестабильный) с полным 14-месячным календарём.
- **Объединённая матрица ABC/XYZ:** сегментация ассортимента на 9 групп для разработки стратегий управления.
- **Проверка сезонности:** выявление SKU с высокой долей продаж в октябре-ноябре (предрождественский пик).
- **Анализ возвратов:** оценка объёма и доли возвратов по кандидатам на вывод.
- **Формирование списка кандидатов:** отбор SKU по комплексу фильтров (ABC/XYZ, клиентская база, активность, цена, новизна, устойчивость в C, полнота клиентских данных).
- **Оценка потенциального эффекта и устойчивости решения:** проверка стабильности списка при сдвиге порогов CV.

---

## 🔧 Основные этапы работы

1.  **Загрузка и первичный анализ данных:**
    *   Загрузка датасета `online_retail.csv` (1 067 371 строк, 8 столбцов).
    *   Анализ пропусков, типов данных, дубликатов и временного диапазона.
    *   Выявление и исследование аномалий: отмены (C-счета), отрицательные количества, нулевые и отрицательные цены, служебные коды, A-счета (корректировки долгов).

2.  **Очистка данных:**
    *   Удаление отменённых заказов (Invoice, начинающиеся с 'C').
    *   Исключение строк с `Quantity <= 0` и `Price <= 0`.
    *   Удаление служебных `StockCode` (POST, DOT, M, BANK CHARGES, ADJUST, AMAZONFEE, gift_*, B и др.).
    *   Нормализация `StockCode`: приведение к верхнему регистру и удаление пробелов.
    *   Удаление полных дубликатов (34 335 строк).
    *   Фиксация периода анализа (14 полных месяцев: 2010-10-01 — 2011-11-30).

3.  **Базовые метрики бизнеса:**
    *   Расчёт количества SKU, заказов, клиентов, проданных единиц и общей выручки.
    *   Анализ динамики по месяцам (сезонность, средний чек).

4.  **ABC-анализ:**
    *   Расчёт выручки по каждому SKU.
    *   Присвоение категорий A, B, C на основе накопленной доли выручки (80/95%).
    *   Визуализация кривой Парето.

5.  **Динамический ABC-анализ:**
    *   Проведение ABC-анализа для каждого полного квартала (2010Q4, 2011Q1, 2011Q2, 2011Q3).
    *   Построение матрицы переходов для отслеживания миграции SKU между категориями.
    *   Выявление «восходящих звёзд» (C → A/B) и «падающих звёзд» (A/B → C).
    *   Расчёт фильтра `StableC` - устойчивое пребывание в категории C во всех активных кварталах.

6.  **XYZ-анализ:**
    *   Построение помесячной динамики продаж для каждого SKU с учётом нулевых месяцев.
    *   Расчёт коэффициента вариации (CV).
    *   Присвоение категорий X, Y, Z на основе пороговых значений CV (0.5 и 1.0).

7.  **Объединённый ABC/XYZ-анализ:**
    *   Создание сводной матрицы, объединяющей ABC и XYZ категории.
    *   Анализ девяти групп (AX, AY, AZ, BX, BY, BZ, CX, CY, CZ) по количеству SKU и доле в выручке.

8.  **Проверка сезонности:**
    *   Выявление SKU с долей выручки в октябре-ноябре выше 20% от общей за период.
    *   Пересечение сезонных SKU с фильтром `StableC` для выявления зоны риска.

9.  **Отбор кандидатов на сокращение:**
    *   Применение комплекса фильтров к группам CZ и BZ: узкая клиентская база (<20 покупателей), низкая активность (<10 месяцев), невысокая цена (≤£10), исключение новинок.
    *   Добавление фильтра `StableC` в альтернативном варианте.
    *   Разделение кандидатов на «основные» (надёжные данные о клиентах) и «требующие ручной проверки» (низкое покрытие клиентских данных).
    *   Сравнение базового и альтернативного вариантов отбора.

10. **Анализ возвратов:**
    *   Оценка объёма и доли возвратов по кандидатам на вывод.
    *   Анализ среднего ReturnRate.

11. **Оценка эффекта и устойчивости:**
    *   Расчёт доли SKU-кандидатов в общем ассортименте и их доли в общей выручке.
    *   Проверка устойчивости решения при сдвиге порогов CV (0.4/0.8 и 0.6/1.2).

- **Сформирован безопасный список на сокращение:** предложено проверить на вывод **611 SKU (15.3%)**, которые приносят всего **0.52% выручки**. Из них 473 SKU основные кандидаты, 138 SKU требуют ручной проверки из-за неполных данных о клиентах.
